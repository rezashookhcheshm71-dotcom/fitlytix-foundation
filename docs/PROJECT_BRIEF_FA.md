> این سند جای «حافظهٔ گفتگو» را می‌گیرد. اگر کسی (یا هر مدل هوش مصنوعی دیگری) فقط همین فایل را بخواند،
> باید بداند پروژه چیست، چه چیزی ساخته شده، چه چیزی واقعاً کار می‌کند، چه چیزی هنوز تأیید نشده، و
> قدم بعدی چیست. هر عددی که اینجا آمده از خود مخزن خوانده شده، نه از حدس.

## ۱) محصول در یک نگاه

FitLytix یک پلتفرم برنامه‌ریزی تمرین و تغذیه برای ورزشکاران ایرانی است، با دو مخاطب:

- **ورزشکار**: برنامهٔ تمرین/تغذیهٔ شخصی، ثبت دادهٔ روزانه، چک‌این، پیشرفت، گذرنامهٔ ورزشی.
- **مربی** (`coach` / `head_coach` / `admin`): فهرست ورزشکاران، توجه لازم، برنامه‌ها، تغذیه، عملکرد،
  و دو نمای تحلیلی که در همین دورهٔ کاری اضافه شد: **کیفیت داده** و **بینش آرکیتایپ**.

هستهٔ ارزش: یک موتور توصیهٔ یادگیری‌ماشین که از ۵۶ ویژگی ورودی، آرکیتایپ برنامه، استراتژی تغذیه،
مدت دوره، حالت مربیگری، تعداد جلسات و نرخ پایبندی مورد انتظار را پیش‌بینی می‌کند؛ و یک **حلقهٔ دادهٔ واقعی**
که پیش‌بینی‌ها را با رفتار واقعی ورزشکار مقایسه و مدل را بازآموزی می‌کند.

اصل حاکم بر همهٔ تصمیم‌ها: **صداقت داده**. هیچ داده‌ای به‌صورت خاموش جعل یا پر نمی‌شود؛ اگر داده کم است،
مدل آن را به‌عنوان «سیگنال غایب» اعلام می‌کند و رابط کاربری همان را نشان می‌دهد.

## ۳) موتور هوش مصنوعی (کامل)

### ۳.۱ آرتیفکت فعلی — دقیقاً چه چیزی روی سرور است

| مشخصه             | مقدار                                                         |
| ----------------- | ------------------------------------------------------------- |
| فرمت              | `fitlytix-gbdt-json` (schema v1)                              |
| نسخهٔ مدل         | `2026.11.11-cce631a`                                          |
| زمان آموزش        | `2026-11-11T10:18:43Z`                                        |
| منبع دادهٔ آموزش  | **`simulated`** — دادهٔ شبیه‌سازی‌شده، نه دادهٔ واقعی ورزشکار |
| ردیف‌ها           | ۴۸٬۰۰۰ (۳۸٬۴۰۰ آموزش / ۹٬۶۰۰ آزمون)                           |
| seed              | ۴۲                                                            |
| ویژگی‌ها          | ۵۶                                                            |
| حجم فایل          | ۱٬۳۰۷٬۱۶۴ بایت، sha256 `2500a09c…49e7e1`                      |
| تطابق TS ↔ Python | ۲۰۰ فیکسچر، بیشترین خطا ۲.۶e-۶ (بدترین: duration)             |

**این جمله باید بدون تغییر بماند**: مدل روی دادهٔ شبیه‌سازی‌شده آموزش دیده است. هر ادعای «آموزش با دادهٔ
واقعی» نادرست است تا وقتی `scripts/retrain.mjs` با ≥ ۲۰۰ ردیف برچسب‌خورده اجرا شود.

### ۳.۲ فضای خروجی

| بُعد             | مقادیر                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| رشته‌ها          | `crossfit`, `hyrox`, `functional`, `bodybuilding`, `running`                                                                  |
| آرکیتایپ         | ۴ در هر رشته = **۲۰ آرکیتایپ** (مثل `cf_foundation`, `cf_strength_skill`, `cf_engine_competition`, `cf_balanced_performance`) |
| تغذیه            | `fat_loss_deficit`, `lean_gain`, `performance_fuel`, `maintenance`, `recomp`                                                  |
| مدت              | ۱، ۳، ۶، ۱۲ ماه                                                                                                               |
| مربیگری          | `ai`, `hybrid`, `human`                                                                                                       |
| خروجی‌های پیوسته | جلسات در هفته (`sessions`) و پایبندی مورد انتظار (`adherence` ۰..۱)                                                           |

### ۳.۳ کیفیت (روی مجموعهٔ آزمون شبیه‌سازی‌شده)

| سربرگ             | معیار    | مدل             | خط مبنای اکثریت |
| ----------------- | -------- | --------------- | --------------- |
| برنامه (crossfit) | accuracy | ۰٫۸۵۱۴          | ۰٫۴۷۱۲          |
| تغذیه             | accuracy | ۰٫۹۴۰۶          | ۰٫۲۹۶۹          |
| مدت               | accuracy | ۰٫۷۳۸۵          | ۰٫۵۱۴۷          |
| مربیگری           | accuracy | ۰٫۷۸۰۵          | ۰٫۵۲۰۹          |
| جلسات             | MAE / R² | ۰٫۲۵۴۷ / ۰٫۸۳۳۷ | —               |
| پایبندی           | MAE / R² | ۰٫۰۶۵۷ / ۰٫۷۹۷۵ | —               |

این اعداد معیار «درست کار کردن کد» هستند، نه اعتبار علمی برای جمعیت واقعی. اعتبار واقعی فقط از
حلقهٔ داده (بخش ۴) می‌آید.

### ۳.۴ گاردریل‌ها (قواعد ایمنی که مدل را محدود می‌کنند)

خروجی مدل هرگز مستقیم به کاربر نمی‌رود؛ ابتدا روی آن قواعد ایمنی اعمال می‌شود و هر تغییر با یک
`SafetyFlag` (برچسب فارسی + اقدام + شدت) به کاربر توضیح داده می‌شود:

`low_sleep` · `high_stress` · `low_readiness` · `low_adherence` · `underweight` · `minor_athlete`
(زیر ۱۶ سال → بازبینی انسانی) · `high_volume_cap` (سقف جلسات بر اساس زمان واقعی) · `nutrition_risk`

اقدام‌ها: کاهش حجم هفته، کوتاه‌کردن دوره، ارتقای حالت مربیگری به `hybrid`/`human`، تغییر هدف تغذیه،
و سقف‌گذاری روی تعداد جلسات. این بخش (`guardrails.ts`) نباید بدون بازبینی ورزشی تغییر کند.

### ۳.۵ چرخهٔ آموزش و استنتاج

1. `ml/train.py` (Python، لوکال) → `model.json` + `metrics.json` + `parity_cases.json`
2. تغییر آرتیفکت → `node scripts/check-model-parity.mjs` باید پاس شود (TS == sklearn)
3. `npm run build` → آرتیفکت داخل بستهٔ Nitro می‌رود
4. رانتایم: `model.server.ts` آرتیفکت را یک‌بار می‌خواند و در TS استنتاج می‌کند (بدون پایتون)
5. هر پیشنهاد در `recommendation_snapshots` ذخیره می‌شود (ورودی، بردار، سیگنال‌های مصرف‌شده/غایب، اقدام)

بازآموزی با دادهٔ واقعی: `node scripts/retrain.mjs --dataset <jsonl> --min-labelled 200` — این اسکریپت
زیر آستانه **عمداً امتناع می‌کند** تا نویز وارد مدل نشود.

## ۴) حلقهٔ داده (قلب پروژه)

```
پیشنهاد برنامه ──► recommendation_snapshots (ورودی + بردار + سیگنال‌ها + اقدام)
                            │
ورزشکار ثبت می‌کند ──► training_sessions / nutrition_logs / athlete_checkins
                            │
                    recommendation_outcomes (پایبندی، جلسات، RPE، دورهٔ کامل، پیشرفت)
                            │
              /api/dataset-export  ──►  data/datasets/dataset-*.jsonl + report.json
                            │
        scripts/loop-status.mjs  ──►  «چقدر تا بازآموزی مانده؟»
                            │
        scripts/retrain.mjs --min-labelled 200  ──►  مدل جدید + parity
```

### جداول

| جدول                                  | مهاجرت  | نقش                                                                            |
| ------------------------------------- | ------- | ------------------------------------------------------------------------------ |
| `recommendation_snapshots`            | ۰۰۴     | هر پیشنهاد: ویژگی‌ها، بردار ۵۶تایی، سیگنال‌های مصرف‌شده/غایب، اقدام، نسخهٔ مدل |
| `recommendation_snapshots.seq`        | ۰۰۵     | ترتیب قطعی برای «آخرین اسنپ‌شات»                                               |
| `recommendation_outcomes`             | ۰۰۴/۰۰۶ | برچسب واقعی: پایبندی، جلسات، پنجره، تغذیه، RPE، دورهٔ کامل، پیشرفت             |
| `athlete_checkins`                    | ۰۰۶     | خواب، آمادگی، استرس، وزن، یادداشت                                              |
| `training_sessions`, `nutrition_logs` | ۰۰۱     | ثبت رفتاری روزانه                                                              |

### صداقت مسیر داده

- خروجی دیتاست برای هر ردیف `usedSignals` و `missingSignals` دارد؛ سیگنال غایب یعنی مدل N/A گذاشته،
  نه اینکه مقدار جعلی ساخته باشد.
- `report.json` شامل `labelled`، `labelledShare`، `behaviourCoverage` و میانگین‌های واقعی است.
- **وضعیت امروز**: `training_sessions`/`athlete_checkins`/`nutrition_logs`/`outcomes` همه صفر ردیف‌اند؛
  پس دیتاست صفر ردیف برچسب‌خورده دارد. این طبیعی است، نه باگ — تا کسی از رابط کاربری ثبت نکند.

## ۷) محدودیت‌های واقعی محیط (همه از تجربهٔ همین هاست)

1. **`information_schema` ممنوع است** (`#1044`). هر کد یا SQL که به آن تکیه کند می‌شکند؛ جایگزین:
   `SHOW TABLES` / `SHOW COLUMNS` (کد اپ همین کار را می‌کند).
2. **پایتون روی هاست نیست.** آموزش لوکال/CI؛ رانتایم فقط TS.
3. **MySQL 8 است، نه MariaDB.** `ADD COLUMN IF NOT EXISTS` وجود ندارد؛ idempotency با
   `CONTINUE HANDLER FOR 1060` در رویه.
4. **phpMyAdmin از تب SQL سطح سرور** دیتابیس انتخاب‌شده ندارد: `#1046 No database selected`.
   راه‌حل: نام کامل جدول/رویه (`eugtezmj_fitlytix.users`) یا انتخاب دیتابیس از ستون چپ.
5. **`CREATE ROUTINE` ممکن است مجاز نباشد** → نسخهٔ بدون رویه (چند `ALTER` جدا) آماده است.
6. **ترمینال SSH شکننده است**: دستورها تک‌خطی، بدون placeholder (`<...>`)، هر دستور فقط بعد از
   برگشتن prompt کامل. این منبع چند خطای واقعی بوده است.
7. **اپ به دامنهٔ خودش curl نمی‌زند** (loopback ناپایدار روی Passenger)؛ تأیید باید از مرورگر باشد.

## ۱۰) کارهای باز، به ترتیب

1. **بستن مسیر ورود** (تنها کاربستِ فوری، بدون فیچر جدید):
