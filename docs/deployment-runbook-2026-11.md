## ۱. متغیرهای محیطیِ لازم

app فقط این‌ها را می‌خواند (پیمایشِ کاملِ `process.env` در `src/`):

| متغیر | alias | پیش‌فرض | نکته |
|---|---|---|---|
| `DB_HOST` | `MYSQL_HOST` | `127.0.0.1` | |
| `DB_PORT` | `MYSQL_PORT` | `3306` | |
| `DB_NAME` | `MYSQL_DATABASE` | **خالی** | عمداً بدونِ fallback؛ نبودش یعنی `DB_NOT_CONFIGURED` |
| `DB_USER` | `MYSQL_USER` | **خالی** | |
| `DB_PASSWORD` | `MYSQL_PASSWORD` | **خالی** | |
| `PORT` | — | — | پورتِ سرورِ مستقل |

`isDatabaseConfigured()` فقط وقتی true است که `DB_NAME` و `DB_USER` هر دو مقدار داشته باشند؛ وگرنه `getPool()` با `DB_NOT_CONFIGURED: missing …` پرتاب می‌کند و لایه‌ی HTTP آن را به ۵۰ِ صادقانه تبدیل می‌کند. **هیچ رازِ نشست یا کلیدِ خارجیِ دیگری لازم نیست.**

در Terminal میزبان:


## ۴. استقرارِ خودِ app

بیلدِ مستقل است (`nitro.preset = "node-server"`)؛ پس روی میزبان نیازی به build نیست:

1. محتوای `.output/` را (سرور + کلاینت) روی میزبان بگذارید.
2. سرور را با node همان nodevenv اجرا کنید: `node .output/server/index.mjs` با `PORT` و متغیرهای `DB_*`.
3. اگر میزبان Passenger است، entry را به `.output/server/index.mjs` اشاره دهید.
4. `allowedHosts: [".e2b.app"]` فقط مربوط به dev-server است و روی بیلدِ پروداکشن اثر ندارد.

## ۷. بازگشت (rollback)

بیلد قبلی را نگه دارید؛ استقرار یعنی فقط عوض‌کردنِ پوشه‌ی `.output` و restart. مهاجرت‌ها بازگشت‌پذیر طراحی نشده‌اند — پس **قبل از اعمالِ هر مهاجرت، از دیتابیس dump بگیرید.**

## ۸. محدودیت‌های این سند

- هیچ‌کدام از صفحه‌ها در این سندباکس با مرورگر دیده نشده‌اند؛ قضاوتِ بصری با کاربر است.
- این سندباکس هیچ مسیرِ شبکه‌ای به میزبان یا MySQL آن ندارد؛ هر اجرای سمتِ سرور باید توسط کاربر انجام شود.
- قیمت‌ها و وعده‌های پولی هنوز رتیفیه نشده‌اند؛ مسیرِ پرداخت mock است و پیش از پولِ واقعی باید بسته شود.
